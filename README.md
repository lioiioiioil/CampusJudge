# CampusJudge

Автономная платформа для преподавателя программирования: темы и ссылки на занятия,
домашние задания, контесты и история решений учеников. Backend на Go, локальные
JSON-файлы, без БД, CI и облачных зависимостей. Для автоматической проверки нужны Go и локальный Linux Docker; внешний сервис не используется.

## Что уже работает

- Вход преподавателя и регистрация ученика по коду группы.
- Темы с внешней HTTPS-ссылкой на занятие — Телемост или другой видеосервис.
- Задачи с примерами и скрытыми тестами, независимые копии задач и версии тестов.
- Домашние задания и контесты с редактируемыми черновиками, доступом по группам и сроками.
- Автоматическая проверка C++, C, Python, Go, Java и JavaScript по примерам и скрытым тестам.
- Шаблоны полных программ, черновики отдельно для каждого языка и автоматическое обновление результата.
- Пробный запуск по примеру или своему вводу, проверка эталонного решения преподавателем.
- Повтор после сбоя, перепроверка на выбранной версии тестов и история вердиктов.
- Ручная проверка остальных языков и комментарии преподавателя.
- Светлая и тёмная темы, двухпанельная рабочая область задачи.
- Табель преподавателя по каждой работе, история посылок и таблица результатов контеста.
- Сохранение данных и сессий после перезапуска.

Решение проходит очередь → компиляцию → тесты; результат появляется в открытом
редакторе автоматически. Вердикты: Accepted, Wrong Answer, Compilation Error,
Runtime Error, Time Limit, Memory Limit и Output Limit. Сбой исполнителя показан
отдельно и не добавляет штрафа. Исходники запускаются только в ограниченных
Linux-контейнерах. Для языков без исполнителя явно указана ручная проверка.

Начальные данные: только тестовая группа, домашка, контест и две простые задачи.
Учеников, тем, посылок и статистики нет. Рабочие данные никогда не попадают в Git.

## Запуск

Нужен Go 1.25 или новее и Linux Docker с cgroup v2. Внешних Go-зависимостей нет.
На macOS можно использовать отдельную Colima VM; команды настройки и ограничения
описаны в [руководстве автоматической проверки](docs/automatic-judge.md).
Один раз соберите локальный образ с компиляторами:

```sh
docker build -t campusjudge-runner:local -f judge/Dockerfile .
```

Затем запустите сервер:

```sh
go run ./cmd/campusjudge
```

При первом запуске сервер выведет логин `teacher`, случайный пароль преподавателя
и код тестовой группы. Сохраните их: пароль повторно не выводится. При желании
задайте начальный пароль через переменную окружения `CAMPUS_TEACHER_PASSWORD`
(от 8 до 128 символов). Она применяется только к новому хранилищу.

Откройте `http://127.0.0.1:8080`. Интерфейсы преподавателя и ученика различаются
по роли аккаунта; сервер дополнительно проверяет права на каждом запросе.

Для локального знакомства с публичным тестовым паролем:

```sh
go run ./cmd/campusjudge -demo -data data/demo.json
```

В этом режиме: `teacher` / `campus-demo`; код регистрации ученика — `DEMOCLASS`.
Ученик создаёт свой аккаунт сам. Demo разрешён только на loopback-адресе.

Для доверенной локальной сети используйте обычный режим и свой адрес:

```sh
go run ./cmd/campusjudge -addr 0.0.0.0:8080
```

Ученики открывают `http://<IP преподавателя>:8080`. Для доступа через интернет
нужен HTTPS перед сервером. Для своего reverse proxy укажите точный CIDR в
`-trusted-proxies` (например, `127.0.0.1/32` для локального прокси). Прокси должен
добавлять клиентский адрес в `X-Forwarded-For` и перезаписывать
`X-Forwarded-Proto` фактической схемой. Ссылки на занятия ведут во внешний видеосервис.

## Первое занятие

1. Войдите преподавателем. В разделе «Ученики» создайте группу и скопируйте её код.
2. Ученики регистрируются по коду группы и входят в свои аккаунты.
3. В разделе «Темы и задачи» добавьте тему, ссылку на видеозанятие и задачи.
4. Создайте домашку для группы. Сначала можно сохранить её черновиком;
   после занятия нажмите «Открыть доступ».
5. Ученик выбирает задачу и язык, вставляет код или загружает файл. В «Пробном
   запуске» можно проверить пример из условия или ввести свои данные.
6. Для поддерживаемого языка вердикт появляется автоматически. В «Табеле» преподаватель
   видит прогресс группы, открывает исходники и может оставить комментарий или оценить
   решение вручную. Ручная оценка имеет приоритет над автоматической проверкой.

Контест создаётся аналогично, с временем начала и окончания и таблицей результатов.
В банке задач можно скопировать задачу, сохранить новую версию тестов и проверить
эталон. Версию для новых посылок выбирают в конкретной работе. Ранее полученный
вердикт действует до успешной перепроверки, после которой он сохраняется в истории.

## Данные и границы

Данные — `data/state.json` (можно изменить через `-data`). Изменения записываются
атомарной заменой файла; при ошибке сохранения запрос возвращает ошибку, а состояние
в памяти не публикуется. Повреждённый файл не сбрасывается автоматически.

Один файл обслуживает **один процесс** сервера. На macOS, Linux и BSD сервер
держит эксклюзивную блокировку соседнего файла `<data>.lock`. Суффикс `.lock`
зарезервирован. Если прежний JSON так назывался, остановите сервер и переименуйте
файл перед обновлением. Переносите рабочий каталог при остановленном сервере.
Пароли хранятся как PBKDF2-SHA256 с солью, токены сессий — как SHA-256.
Это первая одноклассовая версия:
учитель управляет всеми группами экземпляра, темы общие для зарегистрированных
учеников. Черновики работ, чужие исходники и скрытые тесты ученику не выдаются.

Контест использует число решённых задач и штраф: минуты до первого Accepted
плюс 20 минут за каждую предыдущую неуспешную попытку, кроме Compilation Error.
Ожидающие проверки посылки штрафа не дают. Результат определяется временем отправки,
а не временем ручной проверки. Рейтинга уровня Codeforces пока нет. Ошибки инфраструктуры штрафа не дают.

Очередь хранится вместе с посылками и восстанавливается после перезапуска.
Прежние незавершённые решения совместимых языков также подхватываются после обновления;
выставленные преподавателем результаты сохраняются. Один
worker последовательно выполняет задания. В очереди до 64 активных посылок и
до трёх на ученика. Пробный запуск и проверка эталона используют тот же слот,
а их результаты хранятся в памяти до пяти минут.
Режим `-judge manual` работает без Docker и переводит оставшиеся автоматические
задания в состояние, доступное для ручной проверки. Новая версия читает прежние
JSON-файлы; старые бинарники не поддерживают добавленные поля проверки.

## Устройство кода

Правила класса и расчёт результатов — в `internal/domain`; HTTP и сессии —
в `internal/app`; атомарная запись файлов — в `internal/store`. Настройки и запуск
процесса находятся в `cmd/campusjudge`. `internal/judge` владеет контейнерами,
лимитами и сравнением ответов; `internal/app/judging.go` — сохранённой очередью.

Frontend использует нативные ES-модули. `web/app.js` соединяет API, состояние,
контроллер действий и представления. Формы создают проверяемые команды отдельно
от HTTP и DOM. Представления получают снимок данных явно. HTML/CSS/JS встраиваются
в Go-бинарник; сборщик и установка npm-пакетов не нужны.

## Проверка

```sh
go test -race ./...
go vet ./...
```

Необязательные тесты frontend требуют Node.js 22 или новее и используют только
встроенный test runner:

```sh
node --test web/tests/*.test.mjs
```

Проверяются запись и откат транзакций, конкурентные изменения, вход и роли,
публикация домашки, доступ между группами, сроки контеста, сохранность после
перезапуска и расчёт таблицы результатов.

[Архитектура](docs/architecture.md) · [HTTP API](docs/api.md) ·
[Журнал разработки](docs/development.md) · [Сравнение интерфейсов](docs/interface-research.md)

Для явного ручного режима без исполнителя:

```sh
go run ./cmd/campusjudge -judge manual
```

Реальные интеграционные проверки компиляторов и изоляции запускаются отдельно,
с заранее собранным образом; обычные Go-тесты Docker не требуют:

```sh
CAMPUSJUDGE_DOCKER_TESTS=1 go test -v -timeout 15m ./internal/judge
```
