# Журнал разработки

## Шаг 1 — постановка и архитектура

- Зафиксированы темы, домашки, контесты и роли преподавателя и ученика.
- Выбраны Go, локальное файловое хранение и интерфейс без обязательного Node.js.
- БД и CI исключены по текущему запросу.
- До готовности изолированной среды посылки требуют ручной проверки.

Проверено: документы согласованы с текущим запросом; исходники, секреты,
личные данные и учебные решения в начальный коммит не включены.

## Шаг 2 — рабочее ядро на Go

- Добавлены аккаунты, приглашения в группы и серверное разделение ролей.
- Темы содержат внешнюю ссылку на видеозанятие; они доступны до открытия домашки.
- Реализованы задачи, публикация работ, приём исходников, ручная проверка и таблица.
- Состояние сохраняется в JSON через атомарную замену с откатом при ошибке.
- Начальные данные ограничены тестовой домашкой и контестом, без выдуманных учеников.

Проверено: `go test -race ./internal/... ./cmd/...`, `go vet ./internal/... ./cmd/...`.
HTTP-тест проходит путь «тема → черновик → регистрация → публикация → посылка →
проверка → повторное открытие хранилища». Дополнительно проверены чужая группа,
скрытые тесты, права ученика, границы времени и независимый расчёт штрафа.
Независимое ревью выявило скрытие ссылки на урок до публикации домашки; исправлено,
этот сценарий включён в тест. Интерфейс браузера ещё не входит в этот шаг.

## Шаг 3 — отделение правил от транспорта

- Правила работы, видимости, временных границ и таблицы перенесены в чистый
  `internal/domain`; HTTP-обработчики вызывают их внутри транзакций.
- Ответ с состоянием класса стал типизированной проекцией для текущей роли.
- Уровень доступа объявляется у маршрута именованным значением вместо двух bool.
- Начальный пароль и время передаются при инициализации явно; чтение окружения
  осталось в точке запуска. Ошибки хеширования возвращаются вызывающему коду.
- Функциональность и формат API сохранены; ранее записанные файлы продолжают читаться.

Проверено: прежние HTTP-сценарии, `go test -race ./internal/... ./cmd/...`,
`go vet ./internal/... ./cmd/...`; независимое ревью сопоставило JSON-контракты
и транзакционные границы. Замечание о дублирующемся ограничении роли в HTTP
устранено: допуск посылки определяет `domain.CanSubmit`.

## Шаг 4 — модульный интерфейс преподавателя и ученика

- Добавлены разные экраны и действия для двух ролей, создание тем, групп, задач,
  домашних заданий и контестов; публикация и ручная проверка с обратной связью.
- Frontend разделён на нативные ES-модули с явными зависимостями: HTTP, состояние,
  построение команд форм, контроллер эффектов, компоненты и представления.
- Весь интерфейс встраивается в Go-бинарник без сборки. HTTP не выдаёт файлы Go,
  тестов, рабочего состояния и каталоги модулей.
- Асинхронные ответы привязаны к поколению сессии и актуальному запросу снимка.
  Изменения cookie через вход/выход выполняются последовательно.

Проверено: `go test -race ./...`, `go vet ./...`, 28 Node-тестов без зависимостей.
Независимое ревью проверило разделение ответственности и ошибки порядка ответов;
замечания исправлены и закреплены управляемыми асинхронными тестами.

В браузере пройдены создание темы со ссылкой, создание черновика и открытие доступа,
регистрация ученика, отправка кода, ручная проверка и показ комментария ученику,
сохранность после перезапуска, таблица контеста и мобильное меню при ширине 390 px.
Финальная версия повторно запущена с чистым отдельным хранилищем: только две
тестовые работы, без учеников, тем, посылок и вымышленных результатов. Ошибок
в журнале браузера при проверке не обнаружено. Автоматический запуск кода пока
отсутствует; ручной режим явно обозначен в интерфейсе и README.
