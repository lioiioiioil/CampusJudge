# Архитектура первой версии

## Пользовательские сценарии

- Преподаватель создаёт тему, задачи с примерами и тестами, домашнее задание или
  контест. Материал в черновике доступен преподавателю.
- Преподаватель открывает работу группе, задаёт срок или время контеста.
- Ученик входит, видит открытые работы своей группы, выбирает язык и отправляет код.
- Преподаватель видит историю, исходники и результаты своих учеников, получает автоматический
  результат по тестам, оставляет комментарий и при необходимости меняет вердикт вручную.
- Таблица контеста показывает число решённых задач и штрафное время. Для домашки
  важнее прогресс и разбор попыток.

## Компоненты

Один Go-сервер обслуживает HTTP API и встроенные HTML/CSS/JavaScript. Доменный слой
владеет правилами ролей, публикации, сроков и принадлежности ученика группе.
Файловое хранилище сериализует изменения и атомарно заменяет JSON-файл.
Сервер держит эксклюзивную блокировку рядом с файлом данных до завершения процесса.

Автоматическая проверка — отдельная граница `internal/judge`: сохраняемая
очередь API передаёт код Docker supervisor, который компилирует и запускает его
в одноразовых Linux-контейнерах. Хранилище не блокируется во время выполнения.
Worker сохраняет результат, пока посылка принадлежит текущей автоматической
проверке. При ошибке сохранения повторяется запись готового результата.
Для посылки закреплена версия тестов, перепроверка имеет свою целевую версию.
Прежний вердикт действует до успешной перепроверки. При перезапуске
running возвращается в queued; отмена процесса сохраняет задачу для восстановления.

Тесты и ожидаемые ответы остаются у доверенного API; контейнер получает только
текущий вход. Ответы сравниваются по токенам вне контейнера. Автопроверка доступна
для C++, C, Python, Go, Java и JavaScript, остальные языки проверяются вручную.
Лимиты и порядок настройки описаны в [руководстве](automatic-judge.md).

## Инварианты

- Ученик не читает скрытые тесты, чужой код, черновики и работы чужих групп.
- До начала контеста условия скрыты. После закрытия доступны просмотр и история;
  приём новых решений закрыт.
- Ученики не могут назначить себе роль преподавателя или выставить результат.
- Посылка связана с пользователем, работой, задачей и языком; исходный код сохраняется.
- Успешный ответ на изменение означает, что данные записаны на диск.
- Ошибка записи не должна оставлять изменённое состояние только в памяти.
- Изменения данных проверки задач не переписывают историю уже вынесенных результатов.
- Задачи и примеры отображаются как текст; исходники не интерпретируются браузером.
- Автоматическая проверка недоверенного кода не выполняется на хосте веб-сервера.

## Первая граница продукта

Явно исключены пока: рейтинги уровня Codeforces, анти-плагиат, оплаты,
микросервисы, распределённая очередь и мультитенантность. Цель первой версии —
законченный сценарий реального занятия, а не покрытие всего Codeforces.

## Ответственность пакетов

- `internal/model` — сохраняемые сущности и публичный профиль пользователя.
- `internal/domain` — правила доступа и публикации, допуск посылки по времени,
  безопасная проекция класса для роли, расчёт таблицы. Входы — значения и явное
  время; пакет не зависит от HTTP, диска и глобальной конфигурации.
- `internal/store` — сериализация транзакций и сохранение целого состояния.
  Хранилище не знает правил домашки или подсчёта штрафа.
- `internal/app` — HTTP-контракты, сессии, нормализация ввода и границы транзакций.
  Проверка ссылок и допуска выполняется внутри транзакции записи.
- `cmd/campusjudge` — чтение конфигурации, первичная инициализация и жизненный цикл
  процесса. Пароль и время первичного запуска передаются явно.

Изменение правила контеста начинается с `domain` и его поведенческой проверки.
Изменение JSON-формата запроса относится к HTTP-границе; изменение механизма
сохранения не должно менять правила класса. HTTP-тесты дополнительно проверяют
целый путь пользователя и то, какие поля действительно отправляются клиенту.


## Модули интерфейса

`web/app.js` — точка сборки приложения; зависимости передаются явно.
`lib/api.js` владеет HTTP и типизированными ошибками. `lib/state.js` — сменой
аккаунта, маршрута и фильтров, а также чистыми селекторами. `lib/forms.js`
превращает значения формы в проверенную команду без DOM или сети.
`lib/actions.js` координирует эффекты и жизненный цикл экрана. Представления
в `views/` получают снимки данных параметрами; они не загружают и не изменяют
серверные данные. Общие компоненты и форматирование выделены отдельно.

Регрессионные Node-тесты исполняются без зависимостей; Go-тест проверяет, что
все относительные импорты интерфейса встроены в бинарник и выдаются как JavaScript,
а файлы кода Go, тестов и данных не доступны через HTTP.


## Обновление результата и редактор

`lib/theme.js` владеет выбором темы и безопасным сохранением настройки.
`lib/drafts.js` и `lib/editor.js` сохраняют код и выбор языка с явным ключом
пользователя, работы, задачи и языка. Источник шаблонов — каталог API.
`lib/judging.js` отображает публичный результат, не получая скрытые тесты.

Контроллер опрашивает статусы активных автоматических проверок. Исходники
запрашиваются отдельно при открытии посылки.
Тихое обновление меняет результаты и списки, сохраняя DOM редактора и незаполненные
формы преподавателя. Смена аккаунта из другого таба является границей сессии:
старый черновик сохраняется и редактор закрывается до установки нового профиля.
Возврат из BFCache возобновляет опрос с прежними проверками актуальности.
